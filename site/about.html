Project / 项目介绍

一条数据运河，
一只守闸的螃蟹。

Canal Rust 模拟 MySQL slave 的交互协议，向主库发送 dump 请求，接收并解析 binary log 事件， 再通过 protobuf 协议提供给下游消费者。它保留 Java Canal 的 wire protocol，把运行时换成了 Rust。

Apache-2.0Cargo workspacev2.2.0since 2026-07-30

01 / OVERVIEW

把一条变更，
完整地送到下游。

MySQL 在上游不断产生变更，下游消费者随时可能跟不上。中间需要有人控制流量、 保存事件、提供确认。Canal Rust 把这件事拆成 14 个 crate，每一段都独立可测。

Canal Rust 不是另一个 CDC 产品，而是一次尽量克制的重写：协议不变，语义不变，只换实现。

14 个 crate 覆盖了一条完整的链路：接入 → 解析 → 过滤 → 存储 → 输出 → 消费确认。 对外保持与 Java 版 Canal 完全一致的 wire protocol，现有 Java / Go / Python / C# / Node.js 客户端零改动接入。

上游使用 mysql_cdc 连接 MySQL 5.1–8.0 与 MariaDB，支持 position 和 GTID 位点； 解析后的事件会经过正则过滤、环形缓冲、TCP 或 Kafka 输出，最终抵达消费者。

Rust 带来的不是更少的代码，而是更明确的所有权、更轻的运行时，以及一个可以被单独测试和替换的 crate 边界。14 个 crate 的依赖关系是单向的，宠物小运也因此有了一个稳定的落脚点。

02 / ARCHITECTURE

六层职责，
一条单向链路。

从 MySQL 到客户端或 Kafka，每个 crate 只做一件事。层与层之间通过明确的事件模型连接， 异常不会阻塞其余层级的优雅退出。

层Crate职责
接入canal-binlog连接 MySQL、拉取 binlog、转换为统一事件模型
处理canal-filter · canal-sink正则过滤库表，把事件扇出到多个出口
输出canal-store · canal-server · canal-connector环形缓冲存储、TCP 协议服务、Kafka 投递
编排canal-instance管理多个 destination，每个实例独占一条完整链路
运维canal-admin · canal-prometheus · canal-cli启停 API、指标暴露、命令行入口
基础canal-common · canal-proto · canal-meta类型 / 生命周期抽象、protobuf 生成、表结构缓存
data flow
MySQL Master
    │  binlog dump (mysql_cdc)
    ▼
canal-binlog ──▶ canal-filter ──▶ canal-sink ──┬──▶ canal-store ──▶ canal-server ──▶ client
                                                └──▶ canal-connector ──▶ Kafka

canal-instance 管理多个 destination；canal-admin / canal-prometheus 负责启停与指标。

实例、会话、进程三条主线互相独立：任一层异常都不会阻塞其余层级的优雅退出。

03 / DECISIONS

每个选择，
都为了少一点意外。

协议兼容是硬约束，其他选择都围绕它服务：成熟的 CDC 库、纯 Rust 的 protobuf、 零外部依赖的 ring buffer，以及能被 tracing 和 Prometheus 看见的运行状态。

决策选择理由
协议兼容复用 Canal .proto存量客户端零改动
binlog 解析mysql_cdc crate成熟 CDC 库，支持 MySQL / MariaDB
异步运行时tokioRust 生态标准
序列化prost + prost-build纯 Rust protobuf
事件存储自定义 ring buffer零外部依赖，基于 VecDeque
配置serde_yamlYAML，与 Java 版 properties 对标
日志tracing结构化日志，span-based
Web 框架axumAdmin API + Prometheus 端点

04 / MASCOT

小运，
数据运河的闸官。

设计上没有把小运画成一只普通的螃蟹，而是把项目的职责直接画成了角色： 控制流量、保存事件、送达下游。十二种表情形态，则让它在不同页面里有点情绪。

小运的锈红色外壳对应 Rust；左钳拧着闸门水轮，决定放多少数据过去； 右钳托着一枚发光的事件，把变更送往下游。上游漂着一卷 binlog 日志，闸下的水里是 已经放行的数据包。脚下的运河，就是整条链路本身。

锈红色外壳Rust
闸门水轮canal-store · ring buffer
右钳托着的事件canal-sink · fan-out
闸下漂着的包canal-server / canal-connector
上游的 binlog 卷轴canal-binlog
