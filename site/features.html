Capabilities / 功能迭代

14 个 crate，
14 种能力，一条链路。

能力不是功能列表，而是链路上的位置：接入、处理、输出、编排、运维、基础。 每一层只负责一件事，合起来才是一条能把变更送到的运河。

01 / MAP

能力地图，
先看全貌。

14 项能力与 14 个 crate 一一对应，分为数据接入、数据处理、数据输出、编排与运维四组。 接入与处理决定“能拿到什么”，输出与运维决定“能送多远、看得多清”。

02 / CAPABILITIES

四组能力，
各管一段。

从 MySQL 主库到客户端或 Kafka，每个 crate 都在链路上有一个明确的位置。 下面的分组按数据流方向排列，而不是按代码目录排列。

数据接入

01 — 03

canal-binlog

连接 MySQL 5.1–8.0 / MariaDB，拉取 binlog，把 TableMap 映射成统一事件模型。

mysql_cdc · position / GTID

canal-proto

复用 Canal 上游 .proto，用 prost-build 生成 Rust 类型，保持 wire protocol 兼容。

CanalProtocol.proto · EntryProtocol.proto

canal-meta

追踪 DDL 变化，缓存表结构，让解析层不必每次都回查主库。

DDL tracking · schema cache

数据处理

04 — 06

canal-filter

基于正则的库表 include / exclude 过滤，把不需要的变更挡在链路之外。

EventFilter · regex

canal-sink

事件扇出：同一份变更可以同时进入环形缓冲和多个 connector。

fan-out · Arc

canal-store

内存 ring buffer 保存事件，容量溢出自动淘汰；客户端 Ack 后推进消费位点。

VecDeque · ack

数据输出

07 — 09

canal-server

Canal wire protocol TCP 服务：握手、鉴权、订阅、取数、确认，与 Java Canal 客户端兼容。

tokio codec · protobuf

canal-connector

Kafka connector，把变更事件序列化为 JSON flat message 投递到消息队列。

rdkafka · JSON flat message

canal-client

Rust 客户端 SDK，订阅事件并以流的方式逐条取用。

connect · subscribe · stream

编排与运维

10 — 14

canal-instance

单进程管理多个 destination，每个实例独占自己的 binlog、store 与 filter。

lifecycle · feed loop

canal-admin

REST Admin API：实例启停、状态查询、落地页与 /pet.svg。

axum · /health · /api/instances

canal-prometheus

暴露 parsed / filtered / dispatched / errors 计数与活跃实例数。

Prometheus · /metrics

canal-cli

命令行入口：server / dump / pet，二进制名 canal-rust。

clap · config loading

canal-common

基础类型、错误、生命周期抽象，以及项目宠物小运的 ASCII 与 SVG 定义。

types · lifecycle · pet

04 / LIMITS

知道边界，
再决定怎么用。

这些限制来自上游依赖或默认配置，不是隐藏的坑。部署前请逐条确认， 尤其是明文连接与 Admin 监听地址。

Security

MySQL 连接是明文的

上游 mysql_cdc 0.2.1 未实现 TLS，对任何非 Disabled 的 SslMode 直接 panic。账号密码与 binlog 数据都不加密，只在可信内网使用；跨网段请套 SSH 隧道。

Auth

认证插件有限

只支持 mysql_native_password 与 caching_sha2_password。使用 sha256_password 的账号会连接失败，建账号时显式指定认证插件。

Bind

Admin 默认只在本机

未设置 server.admin_bind 时，Admin API 固定在 127.0.0.1:{主端口+1}。容器或远程访问必须显式绑定，并确保防火墙保护。

Metrics

/metrics 默认无认证

Metrics 端点未配置认证时会打印警告。默认只监听回环地址；如果对外暴露，请放在内网或反向代理的鉴权后面。

完整的安全说明与部署建议见 安装文档 与 使用说明。
