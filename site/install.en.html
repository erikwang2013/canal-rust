Get started / Installation

Connect the canal
to your MySQL.

From clone to first event takes about five minutes. You need Rust 1.85+, protoc and MySQL 5.7+ / 8.0 with ROW binlog. Kafka is optional.

Rust 1.85+protoc requiredMySQL 5.7+~5 min

Requirements

  • Rust 1.85+. clap, getrandom and other dependencies use edition 2024; older toolchains cannot build the current Cargo.lock.
  • protoc (Protocol Buffers compiler). canal-proto/build.rs drives prost-build; without protoc every build fails.
  • MySQL 5.7+ / 8.0 with binlog enabled and binlog_format=ROW; MariaDB is supported.
  • Kafka (optional), only when you need a message-queue exit.
  • Ports: 11111 Canal TCP, 11112 Admin API, 9090 Prometheus (all configurable).
install dependencies
# Rust (if not installed)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Debian / Ubuntu
sudo apt-get update && sudo apt-get install -y protobuf-compiler

# macOS
brew install protobuf
Without protoc, builds fail with Could not find 'protoc'. Install it before retrying.

Get the source

The repository contains 14 workspace crates, proto definitions, Docker configuration and documentation.

terminal
git clone https://github.com/erikwang2013/canal-rust.git
cd canal-rust

Build

terminal
cargo build --release

# binary: target/release/canal-rust
./target/release/canal-rust --version
./target/release/canal-rust pet

canal-rust pet prints the ASCII mascot and the places where Xiaoyun lives in the code.

Configure MySQL

Create a replication account for Canal Rust and confirm that binlog is enabled.

MySQL
CREATE USER 'canal'@'%' IDENTIFIED WITH mysql_native_password BY 'canal';
GRANT SELECT, REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO 'canal'@'%';
FLUSH PRIVILEGES;

SHOW VARIABLES LIKE 'log_bin';
SHOW VARIABLES LIKE 'binlog_format';
SHOW MASTER STATUS;

If binlog_format is not ROW, set it in MySQL configuration and restart:

my.cnf
[mysqld]
server-id = 1
log-bin = mysql-bin
binlog_format = ROW
Connections are plaintext. Upstream mysql_cdc 0.2.1 has no TLS; credentials and binlog data are unencrypted. Use a trusted network or an SSH tunnel. Auth plugins are limited to mysql_native_password and caching_sha2_password.

Configure canal.yaml

Copy the template and adjust it for your environment:

terminal
cp canal.yaml.example canal.yaml
canal.yaml
canal:
  mysql:
    host: "127.0.0.1"
    port: 3306
    username: "canal"
    password: "canal"
  store:
    buffer_size: 16384
  server:
    bind: "0.0.0.0:11111"
    metrics_bind: "127.0.0.1:9090"
    # admin_bind: "0.0.0.0:11112"
  logging:
    level: "info"
    format: "json"
FieldDefaultDescription
server_id1001MySQL replication server ID; unique in the cluster
start_journal_namemysql-bin.000001Starting binlog file
start_position4Starting position
store.buffer_size16384Ring buffer capacity
server.bind127.0.0.1:11111Canal TCP listen address
server.metrics_bind127.0.0.1:9090Prometheus /metrics address
server.admin_bind127.0.0.1:{port+1}Admin API; loopback unless set
server.idle_timeout_secs3600Idle client disconnect timeout
filter.pattern.*\..*Schema/table include regex
auth_tokenemptyEmpty = authentication disabled

Run the server

terminal
./target/release/canal-rust server --config canal.yaml

# or
cargo run --release -- server --config canal.yaml

Startup logs include Xiaoyun is on duty, guarding the data canal, followed by the Canal TCP, metrics and Admin API addresses. Ctrl-C triggers graceful shutdown; the binlog task waits up to 5 seconds.

SubcommandPurpose
serverStart Canal TCP, metrics and Admin API
dumpConnect to MySQL and print binlog events
petMeet Xiaoyun and locate the vector original

Docker

Compose builds the image, publishes 11111 / 11112 / 9090 and mounts docker/canal.yaml. The default config reaches a MySQL on the host through host.docker.internal.

terminal
docker compose -f docker/docker-compose.yml up -d

# logs
docker compose -f docker/docker-compose.yml logs -f canal-rust

Edit docker/canal.yaml and restart the container; no image rebuild is needed.

Inside a container, bind to 0.0.0.0 or published ports cannot reach the service. The Docker config already does this.

Verify

terminal
# health
curl http://127.0.0.1:11112/health

# instance status
curl http://127.0.0.1:11112/api/instances

# metrics
curl http://127.0.0.1:9090/metrics

# Admin landing page: Xiaoyun and live status
# http://127.0.0.1:11112/

/health returns status: "UP" with version and uptime; /metrics exposes canal_events_parsed_total, canal_events_dispatched_total and canal_instances_active.

Seeing Xiaoyun and UP means the Admin API is running. Next, write a client or use canal-rust dump to watch the binlog.

Troubleshooting

SymptomFix
Could not find 'protoc'Install protobuf-compiler / protobuf and confirm protoc --version.
sha256_password auth plugin is not supportedUse mysql_native_password or caching_sha2_password.
Cannot connect to MySQLCheck binlog is on, format is ROW, the account has REPLICATION privileges, and server_id is unique.
Admin is unreachable from a container / remote hostSet server.admin_bind: "0.0.0.0:11112" and check the firewall.
Address already in useChange server.bind, metrics_bind or admin_bind.
No eventsConfirm writes occur; use canal-rust dump; check filter.pattern.
