Get started / 安装文档

把运河，
接到你的 MySQL 上。

从 clone 到第一条事件，大约五分钟。需要 Rust 1.85+、protoc，以及一个开启了 ROW 格式 binlog 的 MySQL 5.7+ / 8.0。Kafka 是可选的。

Rust 1.85+protoc requiredMySQL 5.7+~5 min

环境要求

  • Rust 1.85+。依赖链中的 clap、getrandom 等已使用 edition 2024，低于 1.85 无法构建当前 Cargo.lock。
  • protoc（Protocol Buffers 编译器）。canal-proto/build.rs 通过 prost-build 生成代码，缺了它任何编译都会失败。
  • MySQL 5.7+ / 8.0，开启 binlog 且格式为 ROW；MariaDB 也受支持。
  • Kafka（可选），仅在需要消息队列出口时安装。
  • 端口：11111 Canal TCP、11112 Admin API、9090 Prometheus（均可配置）。
安装依赖
# Rust（如果还没装）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Debian / Ubuntu
sudo apt-get update && sudo apt-get install -y protobuf-compiler

# macOS
brew install protobuf
缺少 protoc 时，编译会报 Could not find 'protoc'。这不是 Rust 版本问题， 先把 protoc 装好再重试。

获取源码

仓库包含 14 个 workspace crate、proto 定义、Docker 配置与文档。

terminal
git clone https://github.com/erikwang2013/canal-rust.git
cd canal-rust

构建

terminal
cargo build --release

# 二进制位于 target/release/canal-rust
./target/release/canal-rust --version
./target/release/canal-rust pet

canal-rust pet 会打印 ASCII 版小运，并告诉你它都住在代码里的哪些位置。

配置 MySQL

创建一个供 Canal Rust 使用的复制账号，并确认 binlog 已开启。

MySQL
CREATE USER 'canal'@'%' IDENTIFIED WITH mysql_native_password BY 'canal';
GRANT SELECT, REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO 'canal'@'%';
FLUSH PRIVILEGES;

SHOW VARIABLES LIKE 'log_bin';
SHOW VARIABLES LIKE 'binlog_format';
SHOW MASTER STATUS;

如果 binlog_format 不是 ROW，在 MySQL 配置中设置后重启：

my.cnf
[mysqld]
server-id = 1
log-bin = mysql-bin
binlog_format = ROW
连接是明文的。上游 mysql_cdc 0.2.1 未实现 TLS，账号密码与 binlog 数据都不加密。只在可信内网使用；跨网段请套 SSH 隧道。认证插件仅支持 mysql_native_password 与 caching_sha2_password。

配置 canal.yaml

从模板复制一份，按实际环境修改：

terminal
cp canal.yaml.example canal.yaml
canal.yaml
canal:
  mysql:
    host: "127.0.0.1"
    port: 3306
    username: "canal"
    password: "canal"
  store:
    buffer_size: 16384
  server:
    bind: "0.0.0.0:11111"
    metrics_bind: "127.0.0.1:9090"
    # admin_bind: "0.0.0.0:11112"
  logging:
    level: "info"
    format: "json"
字段默认说明
server_id1001MySQL 复制 server_id，集群内需唯一
start_journal_namemysql-bin.000001起始 binlog 文件
start_position4起始位点
store.buffer_size16384ring buffer 容量
server.bind127.0.0.1:11111Canal TCP 监听地址
server.metrics_bind127.0.0.1:9090Prometheus /metrics 地址
server.admin_bind127.0.0.1:{主端口+1}Admin API；不设则仅本机可达
server.idle_timeout_secs3600客户端空闲断开时间
filter.pattern.*\..*库表 include 正则
auth_token空空 = 不启用认证

启动服务

terminal
./target/release/canal-rust server --config canal.yaml

# 或者
cargo run --release -- server --config canal.yaml

启动日志会出现 小运 is on duty, guarding the data canal，并分别打印 Canal TCP、 Metrics 与 Admin API 的监听地址。按 Ctrl-C 触发优雅关闭，binlog 任务最多等待 5 秒。

子命令用途
server启动完整服务：Canal TCP、Metrics、Admin API
dump直接连接 MySQL，把 binlog 事件打印到终端
pet见一见小运，并查看矢量原图的位置

Docker 部署

compose 会构建镜像、发布 11111 / 11112 / 9090 三个端口，并把 docker/canal.yaml 挂载进容器。默认通过 host.docker.internal 连接宿主机上的 MySQL。

terminal
docker compose -f docker/docker-compose.yml up -d

# 查看日志
docker compose -f docker/docker-compose.yml logs -f canal-rust

修改 docker/canal.yaml 后重启容器即可生效，无需重新构建镜像。

容器内必须监听 0.0.0.0，否则宿主机的端口映射连不上。Docker 配置已经这样设置； 如果你自己写 compose，请保留 bind、metrics_bind 与 admin_bind。

验证

terminal
# 健康检查
curl http://127.0.0.1:11112/health

# 实例状态
curl http://127.0.0.1:11112/api/instances

# 指标
curl http://127.0.0.1:9090/metrics

# 浏览器打开 Admin 落地页，可以看到小运和实时状态
# http://127.0.0.1:11112/

/health 返回 status: "UP" 与版本 / 运行时长； /metrics 中可以看到 canal_events_parsed_total、 canal_events_dispatched_total 与 canal_instances_active。

看到小运和 UP，就说明 Admin API 已经起来了。下一步可以写一个客户端， 或者用 canal-rust dump 先看看 binlog 里有什么。

故障排查

症状处理
Could not find 'protoc'安装 protobuf-compiler / protobuf，确认 protoc --version 可用。
sha256_password auth plugin is not supported改用 mysql_native_password 或 caching_sha2_password 建账号。
连接不上 MySQL确认 binlog 已开启、格式为 ROW、账号具备 REPLICATION 权限、server_id 未被占用。
容器 / 远程打不开 Admin显式设置 server.admin_bind: "0.0.0.0:11112"，并检查防火墙。
Address already in use修改 server.bind / metrics_bind / admin_bind 的端口。
没有事件输出确认有写入发生；用 canal-rust dump 直接观察 binlog；检查 filter.pattern 是否过滤掉了目标库表。
还有问题？先看 使用说明 的配置章节，或到 GitHub Issues 搜索。
