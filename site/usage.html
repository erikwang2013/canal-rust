用 Rust 客户端订阅

canal-client 是仓库自带的 Rust SDK。连接后订阅 destination， 事件会以流的方式返回；每次 next_event() 取到一条。

main.rs
use canal_client::CanalClient;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut client = CanalClient::new("127.0.0.1", 11111)
        .with_destination("example");

    client.connect().await?;
    let mut stream = client.subscribe(None).await?;

    while let Some(Ok(event)) = stream.next_event().await {
        println!("{}: {} @ {}.{}", event.journal_name, event.position,
                 event.schema_name, event.table_name);
    }
    Ok(())
}

事件里包含 journal 名、位点、库名、表名与 DML / DDL 信息。完整示例与端到端测试在 crates/canal-client/tests/e2e.rs。

Java / Go / Python / C# / Node.js 客户端无需改动：Canal Rust 复用上游 CanalProtocol.proto 与 EntryProtocol.proto，保持 wire protocol 兼容。

命令行

terminal
# 启动服务
./target/release/canal-rust server --config canal.yaml

# 直接观察 binlog 事件
./target/release/canal-rust dump --config canal.yaml

# 见见小运
./target/release/canal-rust pet

dump 会连接 MySQL 并逐条打印事件：计数、journal / position、schema.table、 entry type，以及 DDL SQL 或 DML 类型。它不启动 TCP 服务，适合在部署前确认账号权限和位点。

场景 1：同步到 Kafka

把某个库的变更过滤出来，投递到 Kafka topic。消息格式是 JSON flat message。

canal.yaml
canal:
  mysql:
    host: "10.0.0.1"
    username: "replicator"
    password: "secret"
  filter:
    pattern: "mydb\\..*"
main.rs
use canal_connector::kafka::{KafkaConfig, KafkaConnector};
use canal_instance::{CanalInstance, InstanceConfig};
use canal_common::{FilterPattern, LogPosition};
use std::sync::Arc;

let kafka_config = KafkaConfig::new("localhost:9092", "mysql-changes");
let kafka = Arc::new(KafkaConnector::new("kafka-sync", kafka_config).unwrap());
let config = InstanceConfig {
    destination: "mydb-sync".into(),
    mysql_host: "10.0.0.1".into(),
    mysql_port: 3306,
    mysql_username: "replicator".into(),
    mysql_password: "secret".into(),
    mysql_server_id: 2001,
    start_position: LogPosition::new("mysql-bin.000001", 4),
    filter: FilterPattern { pattern: "mydb\\..*".into(), black_list: "".into() },
    store_buffer_size: 16384,
    connector_names: vec!["kafka-sync".into()],
};

连接器通过 canal-sink 扇出接入同一条实例链路；同一个变更可以同时进入 ring buffer 与 Kafka，互不阻塞。

场景 2：多实例

canal-instance 允许一个进程运行多个 destination。每个实例有自己的 binlog 位点、过滤规则与 store，适合在一个 Canal Rust 进程里隔离 prod / test。

main.rs
let manager = InstanceManager::new();

manager.register(CanalInstance::new(
    InstanceConfig { destination: "prod".into(), ..prod_config }, vec![kafka_prod],
)).await;

manager.register(CanalInstance::new(
    InstanceConfig { destination: "test".into(), ..test_config }, vec![kafka_test],
)).await;

manager.start_all().await?;

实例生命周期：已创建 → 启动中 → 运行中（feed() 循环）→ 停止中 → 已停止。

场景 3：Prometheus 监控

terminal
curl http://localhost:9090/metrics

# canal_events_parsed_total 150000
# canal_events_dispatched_total 146800
# canal_instances_active 2
指标类型含义
canal_events_parsed_totalcounter从 MySQL 解析出的 binlog 事件数
canal_events_filtered_totalcounter被过滤规则丢弃的事件数
canal_events_dispatched_totalcounter成功分发到 connector 的事件数
canal_dispatch_errors_totalcounterconnector 分发失败数
canal_instances_activegauge活跃实例数
/metrics 默认无认证。保持 metrics_bind 在回环地址，或放在内网 / 反向代理鉴权之后，不要直接暴露到公网。

场景 4：Admin API

Admin API 默认监听 主端口 + 1 且仅绑定回环地址。要远程或容器访问，必须显式配置 server.admin_bind：

canal.yaml
canal:
  server:
    bind: "0.0.0.0:11111"
    admin_bind: "0.0.0.0:11112"   # 不配置 = 127.0.0.1:11112
terminal
curl http://localhost:11112/health
curl http://localhost:11112/api/instances
curl -X POST http://localhost:11112/api/instances/default/stop
端点用途
GET /无需 token 的落地页：版本、运行时长、实例计数与小运
GET /health健康检查，返回 status / version / uptime_seconds
GET /api/instances实例列表与状态
POST /api/instances/:name/start启动指定实例
POST /api/instances/:name/stop停止指定实例
GET /pet.svg直接返回小运矢量原图

AdminServer 支持通过 with_auth 启用 Authorization: Bearer <token> 校验；CLI 默认未启用 Admin 鉴权，请通过绑定地址与防火墙保护管理端口。

直接用浏览器打开 http://localhost:11112/，会看到小运和实时状态。

运行行为

  • 启动日志打印 小运 is on duty, guarding the data canal，随后分别报告 Canal、Metrics、Admin 的监听地址。
  • binlog 事件按批进入实例：攒到 256 条或每 200ms 刷一次，避免单条事件频繁唤醒下游。
  • 按 Ctrl-C 触发优雅关闭；binlog 任务最多等待 5 秒，把剩余事件刷完后再退出。
  • 客户端空闲超过 idle_timeout_secs（默认 3600 秒）会被断开。
  • ring buffer 容量溢出时自动淘汰最旧事件；客户端 Ack 用于推进消费位点。
完整配置字段与默认值见 安装文档 · 配置 canal.yaml。

开发与测试

terminal
cargo build --release
cargo test --all
cargo clippy --all-targets -- -D warnings
cargo fmt --check --all
cargo doc --open

测试不集中放在顶层 tests/，而是与源码同 crate 维护：单元测试在 src/tests*.rs 或 #[cfg(test)] mod tests，集成测试在 crates/*/tests/。CI 会执行 fmt、clippy、build、test 与 doc。
